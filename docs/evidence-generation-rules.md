# 半年报证据生成规则

本项目的证据是原始资料中可独立理解、可回到原文定位的语义片段。AI 只负责候选结构化，最终证据文本必须来自解析后的原文。

## 保留

- 完整要求、禁止、限制、定义、阈值和适用条件
- 标题与其后第一段正文合并后的陈述
- 列表引导句与列表项合并后的完整要求
- 表格中包含字段名、数值和判断条件的完整行
- 原始文件名、页码/幻灯片/工作表/行号、章节路径、时间戳和 OCR 状态

## 丢弃

- 文件类型、设计规范、版本、作者、日期、目录、封面等元数据标签
- 单个词、单个数字、单位、公式、编号和孤立字段值
- “包括”“如下”“为”等没有后续明细的残缺引导句
- 模型改写、无法在原文中定位的内容

## 处理原则

1. 按章节、条款、段落和列表边界切分，不按固定字符数截断。
2. 标题不能单独成为证据，必须绑定后续语义正文。
3. 相邻碎片只有在能组成完整陈述时才合并；否则拒绝入库。
4. 同文档重复片段去重，但保留所有出现位置。
5. 每条证据标记 `metadata.evidenceKind`，并保留来源定位，供知识卡片引用。

这些规则对应 AuditMind 中的原始块追溯、语义切分、证据质量门禁和服务端原文 grounding 原则；AuditMind 的评审、整改、验证闭环不进入半年报知识卡片主体。

## OCR 质量门禁（V2）

扫描 PDF 的 OCR 结果先进入证据层，不应直接视为可用知识。蒸馏入库前对每条引用执行以下检查：

- 拒绝含明显识别伪影的逐字引用，例如 `灬`、`乛`、`咿`、`ܳ`、替换字符或 `锟斤拷`。
- 拒绝短文本中连续分离数字过多、且缺少中文语义上下文的片段；这类内容通常是表格/公式 OCR 失败。
- 保留原证据和页码供人工复核，但不生成知识卡片，避免污染问题匹配索引。
- 不自动猜测或修正牌号、数值、单位和比较符号；修正必须来自重新 OCR 或人工确认。
- 任何 OCR 引用未通过门禁时，蒸馏批次记录失败原因，支持只重试失败批次。

## 知识覆盖完整性门禁（V1）

- 以原文为基准识别编号条目、章节/小标题，以及“关键、原则、注意、适用、特性、限制、条件、例外”等主题证据。
- 每个重点主题必须至少被一张知识卡片的原文引用覆盖；不能因为不是“必须/不得”句式就跳过定义、机理、特性或选型依据。
- 蒸馏完成后保存 `knowledgeCoverage`：总主题数、已覆盖数、遗漏数、覆盖率和遗漏主题定位。
- 发现遗漏只记录为未覆盖主题，不改写原文、不用外部知识补齐；后续由“补齐遗漏知识”任务按未覆盖证据定向重试。
