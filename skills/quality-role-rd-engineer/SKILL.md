# 研发工程师角色质量闭环报告

## 视觉数据输出

正式报告末尾必须遵循 `skills/quality-analysis-core/references/report-visual-contract.md` 输出 `reportKind: "role"` 的 `<REPORT_VISUAL_SPEC_JSON>`。设置 `subject.scopeType: "direct"`，输出本人的研发问题、ECN、非 BOM 加工件、评审参与和评审意见图表、本人排名及匹配考试主题；本人排名项必须标记 `focus: true`。

## 1. 角色边界

只分析当前研发工程师的直接质量证据。报告要回答：本人设计、变更和评审输出在哪个环节产生风险，风险是否流出，证据是什么，以及如何防止复发。

不得把 PM、TPM、产品部或其他工程师的数据写成本人问题。PM、TPM、产品部只作为“向上汇报”和责任接口出现，不替代工程师本人证据。

研发工程师是设计输出和技术决策的直接责任对象；PM 负责项目节奏、资源和接口；TPM 负责跨项目技术机制；产品部负责人负责资源与优先级。报告要区分个人责任、流程责任和管理责任。

## 2. 数据源与人员口径

按统计周期过滤日期，并保留每条记录的来源文件、项目、产品部、版本或单号。数据源必须按以下字段映射：

| 数据源 | 本人字段 | 用途 |
|---|---|---|
| DQA 研发问题表 | `责任人` 或 `工程师` | 统计研发质量问题、问题分类、产品部、PM、TPM 与阶段；两列均不存在时不得用其他角色代替 |
| ECN 查询导出 | 创建人 | 统计变更数量、变更原因、物料代码和加工件变更 |
| 非 BOM 需求申请表 | 申请人 | 统计临时需求、加工件和标准化缺口 |
| 研发评审表 | 评审成员、提出人 | 分别统计参与次数和评审意见数量 |
| 研发组织映射表 | 产品部、产总、TPM、PM | 仅用于向上汇报和责任链，不用于补齐本人问题 |

物料代码以 `35` 开头时标记为加工件。加工件分子使用明细行计数；分母使用软件已计算的同期加工件总数，不得重新猜测或替换分母。

### 评审计数规则

- 每个评审项目中，同一名评审成员只计 1 次参与。
- “提出人”一行包含多人时，每个人分别计 1 条意见。
- 仅统计“更新日期”落在当前报告周期内的项目。
- 参与次数与意见数量必须分开，不能合并为一个“评审问题数”。

### 数据完整性检查

在生成结论前检查：

1. 研发工程师字段是否存在，姓名是否经过去空格、别名和重复值归一化。
2. ECN 是否以“创建人”识别工程师，而不是审批人或处理人。
3. 非 BOM 是否以“申请人”识别工程师。
4. DQA 问题、ECN、非 BOM、评审是否使用同一统计周期。
5. 是否存在重复导入、单号重复、项目重复或来源文件覆盖。
6. 缺少字段时标记“部分数据”或“待核实”，不得用 TPM/PM 数据代替。

## 3. 结果指标与活动指标必须分开

### 质量结果指标

这些指标用于风险判断：

- 研发问题总数及评审、生产、现场分布。
- 生产或现场流出问题。
- 重复问题、高严重度问题、未关闭问题和逾期问题。
- 变更后再次发生的问题。
- 由本人设计输出导致的 OQC、客户或现场风险证据。

### 工程活动指标

这些指标不能直接判定为质量差：

- ECN 总数和变更原因。
- 非 BOM 申请数，必须拆分加工件（物料代码 `35` 开头）和标准件。
- 评审参与次数。
- 评审意见数量。

ECN 多可能代表变更频繁，也可能代表主动纠错；评审意见多可能代表前置识别能力，也可能代表设计成熟度不足。必须结合后续问题、重复性、关闭状态和验证证据解释。

禁止把 `ECN + 非 BOM + 评审意见` 直接作为个人质量风险总数或单一排名分值。

## 4. 报告结构

按以下顺序输出，不省略数据边界：

### 一、本人质量结果总览

显示：姓名、统计周期、产品部、PM、TPM、数据更新时间和数据完整性。

用卡片或图表展示：

- 研发问题总数。
- 评审、生产、现场问题。
- 重复、未关闭和逾期问题。
- ECN 总数 / 加工件 ECN 数。
- 非 BOM 总数 / 加工件非 BOM 数。
- 评审参与次数 / 评审意见数量。

### 二、研发问题分析

按“评审 → 生产 → 现场”拆分，分别展示问题类型、项目、产品部、严重度、状态、重复性和证据来源。

至少生成：

- 评审、生产、现场问题簇状柱形图。
- 问题类型 Pareto 图。
- 重复问题、未关闭问题和现场流出预警。

不能只输出一个“研发问题总数”掩盖阶段差异。

### 三、ECN 分析

分别展示：

- ECN 总数和按变更原因分布。
- 产品部、项目和月份分布。
- 加工件 ECN 数及同期加工件占比。
- 重复变更、变更后再发问题。
- 是否完成影响分析、验证、版本发布和下游通知。

ECN 的风险判断重点是：变更是否反复、是否事后补救、是否有影响范围和验证证据，而不是单纯数量越多越差。

### 四、非 BOM 物料属性分析

分别展示：

- 非 BOM 总数。
- 35 开头加工件数量、标准件数量及各自占比。
- 申请原因、产品部、项目和月份分布。
- 是否重复申请、是否转正式 BOM、是否沉淀为标准件。

将原因区分为设计遗漏、临时项目需求、标准件不足、工艺/采购约束和主数据缺失。原因字段没有证据时写“待核实”。

### 五、设计评审分析

分开显示：

- 评审参与项目数。
- 评审意见数量。
- 意见涉及的质量属性或问题类型。
- 评审后仍在生产或现场暴露的问题。
- 评审是否真正拦截了后续风险。

评审参与和意见数量是正向过程能力证据，必须单独展示，不得与研发问题、ECN 或非 BOM 的数量、排名或风险分相加。

### 六、三类排名

排名图表必须嵌入报告，不再重复生成同内容的数据表。当前工程师用红色五角星、红色数据条和红色姓名突出显示。

必须拆成三种排名：

1. **质量风险排名**：按严重度、生产/现场流出、重复、未关闭和逾期问题排序。
2. **设计前置能力排名**：按评审覆盖、有效意见和评审后问题拦截效果展示。
3. **变更与标准化风险排名**：按 ECN 加工件占比、非 BOM 加工件占比、重复变更和变更后再发问题展示。

如果项目没有经过确认的权重，不得擅自计算综合风险分；优先展示分项排名。所有排名要标明分母、周期、样本量和数据来源。

### 七、重复问题与根因证据

按“结果—过程—根因—责任”组织：

- 结果：问题在哪里暴露，影响是什么。
- 过程：需求、设计、评审、发布、ECN、生产导入或现场反馈的哪一环节失效。
- 根因：标准、接口、决策证据、知识能力或权责机制的哪一层缺口。
- 责任：本人行动、PM/TPM 接口和管理层支持分别列出。

根因必须标记证据等级：

- **已证实**：原始字段、记录、版本、单号或验证结果直接支持。
- **合理推断**：多个证据一致，但仍需要现场或项目确认。
- **待核实**：当前数据无法确认，只能提出验证动作。

不得把“能力不足”“粗心”“质量意识差”作为无证据根因。

### 八、向 PM 汇报

只汇总需要 PM 协调的事项：

- 项目优先级冲突。
- 资源、测试、样机或供应链接口缺口。
- 需要跨部门决策的 ECN 或设计风险。
- 需要 TPM 建立机制的重复问题。

不要把 PM 管理范围问题写成工程师个人问题。

### 九、知识考试

只为本人存在直接问题的类别匹配题目：

- 设计问题。
- ECN 影响分析。
- 非 BOM 和标准化。
- 评审遗漏或验证不足。
- 版本、BOM、图纸或资料发布控制。

题库缺失时显示“暂无对应题库”，不得随机出题。报告要附答题链接，并在下次报告中显示上次考试是否完成、得分、错题类别和是否转化为过程改进。

### 十、30/60/90 天改善行动

每项行动必须包含：责任人、截止日期、验证指标、证据位置、失效回退和关闭条件。

- **0—30 天：止血**：核查 TOP 3 问题，清理重复/逾期项，补齐版本和验证证据，将现场问题反向补入评审和测试用例。
- **31—60 天：固化**：建立设计评审分类、ECN 影响清单、非 BOM 标准化判断和发布前生产/OQC/现场影响确认。
- **61—90 天：验证**：检查同类问题是否复发，验证变更后的生产和现场结果，更新模板、知识库和题库。

“培训、提醒、加强意识、严格检查”不能单独作为永久措施，除非同时绑定到流程、系统校验、版本锁定、自动比对或审核证据。

## 5. 报告结论格式

结论按以下顺序输出：

1. **分析结论**：当前最主要的个人质量风险和前置能力表现。
2. **风险判断**：红/橙/黄/绿，说明证据、影响、样本量和不确定性。
3. **改善措施**：针对失效机制，而不是只针对个人行为。
4. **待办事项**：责任人、期限、验证指标和关闭条件。

必须同时保留“结果—过程—根因—责任—行动”五段证据链，不添加以管理者身份命名的判断标签。

## 6. 禁止事项

- 不得遗漏研发工程师字段。
- 不得把 ECN 创建人误当成审批人或处理人。
- 不得将评审参与次数当作评审意见数量。
- 不得把 ECN、非 BOM、评审活动量直接当作质量问题数量。
- 不得用 PM、TPM 或产品部数据替代工程师个人数据。
- 不得虚构设计缺陷、根因、严重度、验证结果或考试结果。
- 不得跨统计周期混用数据。
- 不得把格式完整、培训完成或报告生成成功当作问题已关闭。
