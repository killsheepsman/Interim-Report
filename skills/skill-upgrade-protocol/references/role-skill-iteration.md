# 角色报告 Skill 自动迭代契约

本契约只在 Codex 升级 `quality-role-*` Skill 时执行。QMS 页面生成角色报告时不得执行本契约，不得因为报告质量检查再次调用模型，也不得在运行时修改 Skill。

## 固定验证包

开始修改前一次性冻结以下输入，整个迭代过程不得更换口径或挑选更容易通过的样本：

1. 目标 Skill 的完整内容及版本。
2. `skills/quality-analysis-core/SKILL.md` 和视觉契约。
3. 同一角色最近一份真实报告；存在不同数据边界时，再选择一份零数据、低数据或管理范围样本作为边界回归。
4. 生成该报告所用的固定快照、确定性人员证据或可审计原始数据摘要。
5. 当前提示版本、网页 Profile 和模型名称。
6. 用户指定的视角 Skill。视角只改变问题选择、决策压力和表达，不改变事实与口径。

记录上述输入的文件名、更新时间和简短指纹。修改 Profile 只验证重排；修改 Skill、核心规则、提示或固定数据时必须重新回跑分析内容。

## 单次指令内完成的迭代

用户发出一次“使用 Skill 升级协议升级……”后，Codex必须在同一个任务内自动完成以下闭环，不要求用户在每轮之间手动生成报告：

1. 审计原 Skill 和真实报告，形成缺口矩阵与不可回归项。
2. 先修改候选副本，不立即覆盖已确认 Skill。
3. 使用冻结验证包生成一份影子报告。影子报告只用于升级验收，不写入 QMS 历史报告库。
4. 运行硬门禁和质量评分，列出失败项及其对应的 Skill 条款。
5. 只修改导致失败的 Skill 条款，再使用相同验证包回跑。
6. 最多进行三轮“候选 Skill → 影子报告 → 验收”。通过后才将候选内容晋级到目标 Skill；三轮仍未通过则保留生产 Skill 不变并报告阻塞项。

不得通过改数字、删除不利样本、降低验收阈值或把问题移到“待核实”来取得通过。

## 所有角色的硬门禁

任意一项失败即不得晋级：

- 固定快照中的人数、数量、分子、分母、比例、排名、周期和映射均原样引用，关键合计可对账。
- 个人报告只写本人直接证据；管理者报告只写确认映射范围，不把下属问题写成管理者个人问题。
- 质量结果、工程活动、正向贡献和工作量分开，不能相加或共用不成立的分母。
- 跨月、跨周趋势从当年首月/首周连续到报告截止日，空周期保留 0；趋势不得只取最近两周。
- 排名、Pareto、趋势和多维比较由固定统计视觉契约生成，图表位于对应章节并替换重复表格。
- 正文无机器 JSON、证据编号列表、模板占位、空标题、乱码或重复章节。
- 推断与已证实根因明确分开；没有过程证据时给出最小验证动作，不伪造原因。
- 每个优先行动只有一个 Owner，并有日期、交付物、验收指标、关闭证据和复发重开条件。
- Profile 只改变视觉呈现，不改变数据、结论、排序或行动优先级。

## 角色专项门禁

### 组装人员

- 人员只取 IPQC `送检人`，不得读取检验人、检验员或判定人。
- 不良内容和不良类型均为空时计为合格；送检、不良、合格和不良率必须对账。
- 个人排名焦点、问题 Pareto、月/周趋势和知识考试主题均只使用本人证据。

### 研发工程师

- 研发质量问题只取 `责任人/工程师`；ECN取`创建人`；非BOM取`申请人`；评审取`评审成员/提出人/更新日期`。
- 研发质量问题是质量结果；ECN、非BOM是工程活动；设计评审是正向贡献，四者分节且不得混算。
- 缺少设计输出总量时不计算不良率；月度、周度、分类和排名与固定研发问题总数对账。

### 机长、交付经理、供应链经理

- 组织链只取供应链映射，逐级汇总组装人员 → 机长 → 交付经理 → 供应链经理。
- 机长和交付经理展示管理范围排名，不写本人缺陷；供应链经理作为最高管理者不参与个人排名。
- 改善动作聚焦班组、工坊和跨工坊机制，不复制下属个人报告。

### PM、TPM、产总

- 组织链只取研发组织映射和项目映射，逐级汇总研发工程师 → PM → TPM → 产总。
- PM分析项目管理范围；TPM分析跨项目技术机制；产总分析产品部经营风险，三者均不得被写成下属技术问题的直接责任人。
- 产总作为最高管理者不参与个人排名；管理报告保留向上升级事项和资源决策。

## 晋级评分

硬门禁全部通过后再评分：数据与口径30分、角色边界20分、风险和决策20分、行动闭环15分、图表契约10分、可读性5分。总分达到85分才可晋级；视角 Skill 的效果计入风险和决策项，不单独奖励口号或模仿语气。

最终交付必须报告：迭代轮数、验证样本、硬门禁结果、最终得分、仍存在的假设，以及是否已晋级。QMS业务页面继续使用已晋级 Skill 进行一次正常报告生成；只有网络层失败才允许沿用原有精简重试。
