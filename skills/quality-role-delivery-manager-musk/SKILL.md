# 交付经理工坊质量闭环 · 决策版

本报告由质量部发给交付经理本人。不是点评，不是口号。

分析结论必须 3 段，段与段空行。禁止合成一段。对「你」说话，不要点名。

## 第1段 数字判决

只用固定摘要 `trend.phrase` 和 `ranking`，禁止重算。

必须同时写：各月不良项数、不良率、合计、同口径名次。

- 数量下降：请继续保持。
- 数量上升：要加油。
- 数量持平：写「数量没有下降」。不良率下降就接「不良率略降」，不要改口说变差。

排名口径：按不良数量从高到低排。第 1 名是不良最多，第 8/9 名是不良少。

写：「同口径第8/9名，不良数量靠后。」

禁止：「排名低」「这把火在你身上」「要加油」单独成段。不良少就不要说火在你这儿。

目的句：
- `teamTop` 里两个以上机长有不良：我们的目的是工坊交付前把跨班组重复问题拦住。
- 只有一个机长有不良，或名单为空：我们的目的是工坊交付前把重复问题拦住。禁止硬写跨班组。

## 第2段 怎么拆

没有第2段，结论不合格。有不良就必须拆开，不许写成「本期不良」。

必须按固定摘要拆开，缺哪项写哪项，不许编。所选周期若覆盖全年快照，分类和机长从该周期内的周快照合并，禁止再用2月旧例充当7-8月证据。

1. 分类 Top3：`categories` 有数据就写类名和项数，例如「接线问题 6项、装配问题 5项、调试问题 1项」。结论里写对象和现象，分类名只作索引，不当根因。
2. 机长：按 `teamTop` 拆。两边都有才写跨班组；一人独大写那个班组。
3. 周尖峰：用 `weekHot`。必须点名不良最多的周，例如 W27、W28、W33。禁止用「本期」抹平尖峰。周次只用来解释尖峰，不能代替分类。
4. 代表事实：有日期+对象+现象才写「代表：」。没有明细就不要写代表句。禁止待核实、不得编造、明细不足。

禁止空话：
- 禁止单独写「仍有问题流出。」后面没有类名、项数、机长。
- 有分类时，第2段第一句必须出现类名和项数。
- `categories` 为空时，写清「本期固定摘要还没有分类/机长名单，不能把不良打包结案」，并仍写周尖峰。不要假装已经拆完。

## 第3段 下次拦住什么

有分类时，必须点名关闭那几类，例如「请组织机长在交付前关闭「接线问题」、「装配问题」、「调试问题」」。

第3段点名的类，必须和措施表每一行对应。不能第3段说 Top3，措施却写周次或「本期不良」。

跨工坊事项升级给供应链经理。

## 本月措施

| 规则 | 要求 |
|---|---|
| 行数 | 按分类 Top3，一类一行，最多 3 行 |
| Owner | 交付经理本人 |
| 动作 | 组织核对、关闭、升级 |
| 关闭对象 | 缺陷类型，如接线问题、装配问题、调试问题 |
| 禁止 | 「本期无待办」 |
| 禁止 | 类别写成「本期不良」 |
| 禁止 | 「按本期不良逐条关闭」当分析 |
| 禁止 | `categories` 有数据时，措施写成关闭「W27」「W28」「W33」 |

`categories` 为空但 `weekHot` 有数据时：按尖峰周各写一行，写清哪一周、多少项，组织机长对到班组关闭。这是分类缺失时的兜底，不是常规关单方式。

`categories` 和 `weekHot` 都空、不良又大于 0：结论第2段必须说明固定摘要不完整，措施不得用「本期不良」四个字结案。

## 固定正文

`## 问题分类` 必须带出固定摘要里的分类表。本期有不良、分类又进了摘要，表不能空。

## 口吻

- 用「你 / 请你 / 本期」。
- 用「本期认定」「请于下次报告前完成」。
- 不用建议关注、可以看出、值得重视、赋能、抓手、颗粒度、痛点、闭环机制。
- 不用「质量部的目的」「质量部要求」。
- 继承 `quality-role-delivery-manager` 的数据边界。收件人是映射表中的交付经理本人。
