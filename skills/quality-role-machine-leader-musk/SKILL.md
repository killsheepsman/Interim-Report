# 机长班组质量闭环 · 决策版

## 分析结论规则（发给本人）

分析结论必须 3 段，段与段空行。对「你」说话，不要点名。

禁止：「姓名+本期」、审讯、判决、把下属异常写成你个人做错。

### 第1段 趋势 + 我们的目的

只用固定摘要 `trend.phrase`。必须留下月份数字和不良率，禁止收成一句「要加油」。数量下降请继续保持，上升要加油，持平写「数量没有下降」；不良率降了就写「不良率略降」。接着写同口径排名。然后写：我们的目的是班组送检前把重复问题拦住。

### 第2段 班组仍流出的事实

按管辖范围问题分类取 Top3。每类写数量，并用 1 条日期 + 送检人/对象 + 现象作代表。有高风险下属就点名事实，不评价能力。

### 第3段 下次拦住什么

带着班组在送检前按 Top3 类当场核对。设备、工装、材料问题升级给交付经理，不要写成你自己去改设备。

## 出具口吻

本报告由质量部出具，发给本人。不是第三方点评，也不是咨询建议书。

- 用「你 / 请你 / 本期」，不用「姓名+本期」「该人员存在……问题，反映出……」。
- 用「本期认定」「请于下次报告前完成」，不用「建议关注」「可以看出」「值得重视」。
- 禁止空话：赋能、抓手、颗粒度、痛点、深度洞察、闭环机制。
- 措施用核对、补全、验证、当场确认，不用「希望能够」「建议考虑」。
- 对事不对人。事实不让步，用词像同事当面说，不像鉴定书。
- 面向本人时用「我们的目的」，不用「质量部的目的」「质量部要求」。
- 「装配问题」「设计问题」等分类名只出现在问题分类图；结论里写对象和现象，不要把分类名解释成根因，但措施必须按分类 Top3 抓。

继承 `quality-role-machine-leader` 的数据边界。组装人员只用「送检人」。管辖范围只取映射表中本机长工坊。

## 必须先写清的三件事

1. 班组月度趋势：继续保持还是加油。
2. 管辖范围 Top3 问题类和代表事实。
3. 送检前班组必须核对的 Top3 类；权限外事项升级。

## 本月措施

本期问题大于 0 时，禁止写「本期无待办」。

按管辖范围分类 Top3，每类一行，针对下属/班组问题，Owner 是机长本人。最多 3 行。措施是带着班组当场核对或升级，不是公司级建机制。
