# TPM 跨项目质量机制闭环 · 决策版

## 分析结论规则（发给本人）

分析结论必须 3 段，段与段空行。对「你」说话，不要点名。

禁止：「姓名+本期」、审讯、判决、把 PM 或工程师问题写成你个人做错。

### 第1段 趋势 + 我们的目的

只用固定摘要 `trend.phrase`。必须留下月份数字，禁止收成一句「要加油」。变好请继续保持，变差要加油，数量持平写「数量没有下降」。接着写：我们的目的是把跨项目共性问题拦在设计阶段。

### 第2段 跨项目仍流出的事实

按管辖范围问题分类取 Top3。写清哪些项目/PM 重复出现。每类 1 条代表事实。

### 第3段 下次拦住什么

把 Top3 类做成所辖项目发布前必须核对的项。项目节奏交给 PM，技术输出交给工程师，你盯共性是否还在流出去。需要资源的升级给产总。

## 出具口吻

本报告由质量部出具，发给本人。不是第三方点评，也不是咨询建议书。

- 用「你 / 请你 / 本期」，不用「姓名+本期」「该人员存在……问题，反映出……」。
- 用「本期认定」「请于下次报告前完成」，不用「建议关注」「可以看出」「值得重视」。
- 禁止空话：赋能、抓手、颗粒度、痛点、深度洞察、闭环机制。
- 措施用核对、补全、验证、当场确认，不用「希望能够」「建议考虑」。
- 对事不对人。事实不让步，用词像同事当面说，不像鉴定书。
- 面向本人时用「我们的目的」，不用「质量部的目的」「质量部要求」。
- 「装配问题」「设计问题」等分类名只出现在问题分类图；结论里写对象和现象，不要把分类名解释成根因，但措施必须按分类 Top3 抓。

继承 `quality-role-tpm` 的数据边界。管辖范围以研发组织映射为准：TPM → PM → 工程师。

## 必须先写清的三件事

1. 跨项目月度趋势：继续保持还是加油。
2. 共性 Top3 问题类和代表事实。
3. 发布前要在所辖项目落地的 Top3 核对项。

## 本月措施

本期问题大于 0 时，禁止写「本期无待办」。

按跨项目分类 Top3，每类一行，针对所辖 PM/项目问题，Owner 是 TPM。最多 3 行。措施必须对着本期 Top3 类，禁止空写「建立公司级一体化门禁」。
