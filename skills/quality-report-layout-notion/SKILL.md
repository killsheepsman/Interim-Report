# Notion 风格质量报告排版

## 核心原则

把报告组织成可扫描、可复查、可继续执行的工作文档。稳定使用标题、短段落、信息块、清单和表格表达不同信息，不用营销式大标题、重阴影或随机彩色装饰。

## 输出顺序

1. 只保留一个一级标题，随后列出统计周期、范围、数据来源、可信度和更新时间。
2. 用“本期结论”快速列出 3—5 项最重要判断，每项包含结论编号和证据编号。
3. 依次输出关键指标、重点风险、结果—过程—根因、责任分层、行动台账和验证关闭。
4. 将待验证事项集中到“待核实”章节，写清验证方法、责任角色和期限。
5. 将 30/60/90 天行动写成可执行表格，便于后续更新状态。

## 图表优先规则

- 对排名、TOP、趋势、分布、供应商对比、缺陷结构和同期对比执行“图表替换数据表”：输出“清晰标题 + 图表就绪 Markdown 数据表”，由页面在同一章节内转换为文档流图表并隐藏原数据表。
- 把图表放在其对应的报告章节，不得集中堆放在报告开头，也不得移动到与数据语义无关的章节。
- Pareto 使用数量柱形图 + 累计占比折线；累计占比必须按排序后的项目逐项累加。
- 良率和月度趋势使用数量柱形图 + 良率折线；同期比较保留 2025/2026 数量与良率系列。
- 人员或管理范围排名使用横向簇状条形图；角色报告突出当前报告对象，不再重复输出排名表。
- 图表数据表第一列必须是类别或时间，其后保留 1—3 个可比较数值系列；不得混合不同量纲。
- 行动、责任、证据、期限、状态、关闭条件和待核实事项继续使用表格或清单。
- 图表后只保留必要的结论和来源，不再重复同一排名数据表。

## Markdown 约束

- 使用 `#`、`##`、`###` 建立稳定文档层级，禁止标题跳级。
- 使用短列表表达结论和待办；一个列表不超过 7 项，超过时按主题分组。
- 重点信息使用粗体；禁止整篇加粗或整篇标红。
- 表格优先用于指标、风险、责任和行动的结构化比较。
- 行动表至少保留：阶段、行动、责任对象、交付物、期限、验证指标、状态、关闭条件。
- 证据编号、K 结论编号、A 行动编号必须原样保留。

## 质量边界

- 不新增、不重算、不修饰任何数字。
- 不把合理推断或待验证假设改写为事实。
- 不删除证据缺口和发布限制。
- 不以排版为理由改变责任层级或行动优先级。
- 输出结构化 Markdown，不输出 CSS、HTML、字体名称或排版说明。
