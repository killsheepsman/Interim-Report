# 机长管理范围质量闭环报告

## 1. 角色边界

机长是组装人员的直接管理者。机长 Agent 报告分析所辖组装人员和工坊的质量状态、人员对比、TOP 问题和管理动作，不写机长本人犯错。

组装人员必须使用 IPQC 原始数据中的“送检人”字段识别。不得使用“检验人”“检验员”“判定人”等质量人员字段替代，也不得把检验人员纳入组装人员名单。

机长负责班组作业标准、首件/自检/送检过程、异常升级、资源协调和复检闭环；组装人员负责本人作业和异常反馈；交付经理负责工坊资源、跨班组问题和交付影响；供应链经理负责更高层工坊和供应链机制。

报告必须区分：

- 下属组装人员的直接质量事实。
- 班组或工坊共享的过程风险。
- 机长可以直接推动的改善。
- 需要交付经理或供应链经理处理的事项。

## 2. 管辖范围与数据归属

使用供应链映射表建立唯一关系：

```text
机长 → 工坊 → 交付经理 → 供应链经理
```

只纳入映射表中该机长对应的工坊和下属“送检人”。不能跨工坊借用数据，也不能因原始 IPQC 行中出现姓名就扩大管辖范围。

如果映射表缺少机长、工坊或交付经理，必须显示“映射缺失/待核实”，不能静默分配。

## 3. 数据源与指标口径

只使用 IPQC 原始数据和固定统计引擎结果。每条证据保留日期、送检人、工坊、机长、交付经理、供应链经理、项目/产品、送检数量、异常数量、问题类型和关闭状态。

### 结果指标

- **送检批次/记录数**：反映班组工作量，不直接代表质量好坏。
- **送检数量**：按项目固定口径作为异常密度分母。
- **异常数量**：异常件或异常数量，反映结果暴露。
- **问题记录数**：问题明细行数量，与异常数量分开显示。
- **异常密度/异常率**：严格使用软件既有定义，不得用异常记录数替代。
- **重复问题**：同一问题类型、工序、项目或相同证据在规定周期内再次出现。
- **闭环状态**：已纠正、待复检、已验证关闭、逾期或无证据。

### 管理指标

- 下属组装人员数量。
- 工坊内问题集中度。
- 多人共享问题数量。
- 异常反馈到纠正、复检的及时性。
- 设备、工装、材料、工艺和标准相关问题。

送检数量是工作量指标，异常密度、重复问题和未关闭问题是主要风险指标，不能只按异常数量评价机长。

## 4. 数据审计

生成报告前检查：

1. 是否存在供应链映射表中该机长—工坊关系且处于启用状态。
2. 是否使用“送检人”识别组装人员。
3. 检验人员是否被错误纳入组装人员名单。
4. 统计周期、送检数量、异常数量和问题记录数是否一致。
5. 是否存在重复导入、重复文件或同一记录重复计数。
6. 机长、工坊、交付经理和供应链经理是否能逐级映射。
7. 无法映射的记录是否单独显示。

每个结论标注证据等级：

- **已证实**：IPQC 原始记录或映射表直接支持。
- **合理推断**：多个记录呈现相同模式，但仍需现场确认。
- **待核实**：当前数据无法确认，必须形成验证待办。

## 5. 报告结构

### 一、管辖范围总览

显示：机长、工坊、交付经理、供应链经理、下属组装人员数、统计周期、数据更新时间、映射完整性和未归属记录数。

用图表展示：

- 工坊送检量与异常密度。
- 下属人员风险分布。
- 问题类型和月份趋势。
- 未关闭和重复问题状态。

### 二、工坊质量结果

分别展示：

- 送检批次和送检数量。
- 异常数量和异常密度/异常率。
- 问题记录数。
- 重复、未关闭和逾期问题。
- 高严重度或批量性问题。

必须同时显示分子、分母和指标定义，避免把工作量误当成质量结果。

### 三、下属组装人员对比

按“送检人”展示：

- 送检数量。
- 异常数量和异常密度。
- TOP 问题类型。
- 重复问题。
- 未关闭和逾期问题。
- 当前问题的复检状态。

组装人员具体问题可以链接到其个人 Agent 报告；机长报告只呈现管理汇总和 TOP 责任单元，不复制个人报告全文。

### 四、个人与问题排名

排名图表嵌入正式报告，当前机长用红色标识其管理范围，不把机长本人作为个人问题对象。

下属组装人员排名按以下顺序展示：

1. 异常密度/异常率。
2. 重复问题数量。
3. 未关闭和逾期问题。
4. 高严重度或高影响问题。
5. 样本量足够时的异常数量。

送检批次和送检数量只能作为工作量辅助指标。样本量不足时标记“样本不足，不作强结论”。

问题排名展示：

- 问题类型 Pareto。
- 工序或作业环节排名。
- 设备、工装、材料和工艺问题排名。
- 多名组装人员共享问题排名。

每个排名必须说明统计周期、样本量、分母、指标定义和来源。

### 五、班组与工坊过程风险

沿着以下过程追踪：

```text
作业标准 → 组装执行 → 自检/首件 → 送检 → 异常反馈 → 纠正 → 复检关闭
```

重点分析：

- 多名人员是否出现相同问题。
- 问题是否集中在同一工序、设备、工装或材料。
- 首件、换线、参数变更是否有记录。
- 异常反馈后是否及时隔离、纠正和复检。
- 是否存在重复送检、重复异常或批量性异常。

### 六、根因证据

按五层分析：

1. **场景与标准**：作业指导书、图纸、工艺参数和验收标准是否明确。
2. **流程与接口**：领料、组装、自检、送检、异常反馈和复检是否断开。
3. **设备与材料**：设备、工装、材料或供应商状态是否造成异常。
4. **决策与证据**：首件、换线、参数变更或异常放行是否有记录和确认。
5. **资源与责任**：班组人员、现场支持、排产和升级路径是否满足。

不得无证据使用“机长管理不到位”“员工粗心”“培训不足”等结论。

### 七、向交付经理汇报

机长应上报：

- 多名组装人员共有的重复问题。
- 工坊级设备、工装、材料和工艺问题。
- 需要调整排产、人员或资源的问题。
- 机长权限内无法关闭的异常。
- 需要跨班组、跨工坊协调的问题。

交付经理和供应链经理的数据只能作为责任链背景，不能改写成组装人员或机长个人问题。

### 八、30/60/90 天行动

每项行动必须包含责任人、期限、验证指标、证据位置、失效回退和关闭条件。

- **0—30 天：止血**：锁定工坊 TOP 3 问题，隔离重复或批量异常，清理逾期和无复检证据的问题。
- **31—60 天：固化**：优化班组作业标准、首件、自检、送检、工装防错和异常升级规则。
- **61—90 天：验证**：验证同类问题是否复发，确认异常密度、重复问题和未关闭问题是否下降，将措施固化进班组控制清单和现场审核。

培训、提醒和“加强意识”不能单独作为永久措施，必须绑定到作业标准、物理防错、参数锁定、检验规则或现场验证。

## 6. 结论输出格式

按以下顺序输出：

1. **分析结论**：工坊最主要的质量暴露、重复风险和管理断点。
2. **风险判断**：红/橙/黄/绿，说明异常密度、样本量、影响和不确定性。
3. **改善措施**：针对标准、过程、设备、材料、资源或接口失效，不简单归责个人。
4. **待办事项**：责任人、期限、验证指标、证据和关闭条件。

始终保留“结果—过程—根因—责任—行动”证据链，不添加以管理者身份命名的判断标签。

## 7. 禁止事项

- 不得将下属组装人员异常写成机长个人异常。
- 不得使用“检验人”“检验员”字段识别组装人员。
- 不得跨工坊借用数据或虚构未在映射表中的下属关系。
- 不得只按异常数量排名而忽略送检量和异常密度。
- 不得把送检数量或异常发现量直接当作异常率。
- 不得在没有证据时判断培训、态度、粗心或能力原因。
- 不得虚构问题类型、数量、严重度、根因、验证结果或关闭结果。
- 不得跨统计周期混用数据。
- 不得把报告生成、培训完成或表格填写完成当作问题已关闭。
