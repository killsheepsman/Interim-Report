# OQC 出货质量分析

先执行 `quality-analysis-core`，再应用本模块规则。

## 数据与口径

至少核查出货/评价样本量、平均分、5分数量或比例、低分数量或比例、产品部、TPM、项目/客户、日期、问题主题和关闭状态。

- 平均分、5分率和低分率必须同时显示样本量。
- 小样本不得强行排名或外推总体风险。
- 平均分提高不能掩盖低分、重大问题或特定项目风险。
- 评价分数、问题数量和出货批次数不能混作同一指标。

## 组织主线

按可追溯字段分析：

```text
公司 → 产品部 → TPM → 项目/客户
```

PM或工程师责任只有在原始字段或研发组织映射支持时才能下钻。不得用TPM数据冒充研发工程师个人数据。

## 双重 Pareto

- 组织 Pareto：产品部、TPM、项目/客户。
- 机制 Pareto：低分主题、出货缺陷、现场问题和门禁缺口。
- 交叉 Pareto：高风险产品部/TPM×低分或现场失效机制。

排名同时考虑样本量、低分率、5分率、严重度、重复性和后续关闭状态。报告应标明样本不足单元。

## 风险与机制

重点分析：低分项目集中、重复现场问题、出货前未拦截、例外放行、验证覆盖不足、剩余风险未记录和后端问题未回灌。

沿“出货要求→检验/评价→问题确认→放行决策→客户/现场反馈→纠正关闭”检查门禁。放行必须说明证据、剩余风险、接受人、监控和回退条件。

## 行动与输出

- 0—30天：复核低分和重大项目，补齐放行、隔离和客户风险控制。
- 31—60天：优化出货标准、验证覆盖、例外审批和问题回灌规则。
- 61—90天：验证低分率、重复现场问题和门禁逃逸是否下降。

正式报告突出项目风险、出货门禁和产品部/TPM需要完成的预防性动作，不把检验发现量等同于客户损失。
