# 跨模块质量链分析

先执行 `quality-analysis-core`，再分别遵守参与模块的专项 Skill。

## 证据连接规则

只在存在追溯证据时连接：

```text
DQA研发/变更 → IQC来料 → IPQC过程 → OQC出货 → QMS客户反馈
```

连接强度：

- **强连接**：相同SN、批次、工单或唯一问题编号。
- **中连接**：相同项目+物料+时间窗，或相同版本+责任组织。
- **弱连接**：仅问题主题、文字或同期趋势相似。

只有强连接可表述为同一质量链；中连接为合理推断且必须验证；弱连接只能表述为共同主题假设。不得因“尺寸、软件、装配”等文字相似就认定跨阶段逃逸。

## 数据审计

检查各模块统计周期、指标口径、数据更新时间和组织映射是否一致；列出可用追溯键、缺失率、冲突值和无法连接的记录。模块间总量不要求相等，但必须解释分析对象和分母差异。

任一关键模块为D级可信度时，不输出端到端强因果结论。

## 分析方法

1. 分别引用各模块已完成的结果和双重Pareto，不重新计算模块指标。
2. 建立追溯键连接表，保留源记录、时间、组织和证据等级。
3. 识别源头发生、前端预防、过程拦截、出货逃逸和客户影响。
4. 区分同一问题链、共同失效机制和仅同期波动。
5. 形成不超过3项公司级质量战役，避免把所有TOP问题简单拼接。

## 责任与行动

跨模块行动必须指定端到端 Owner，同时保留各阶段责任人。重点解决接口、版本、标准、变更、放行和反馈回灌，不把责任全部交给质量部门。

每项战役包含：客户/经营影响、证据链、发生点、应拦截点、实际发现点、逃逸原因、临时控制、永久防错、责任链、30/60/90天计划、验证指标和关闭条件。

## 正式报告

输出：模块可信度矩阵、追溯键覆盖、跨模块质量链、共同机制Pareto、三项公司级战役、端到端责任和验证计划。没有追溯证据的主题必须明确标记“待验证的共同机制”，不得绘制为已证实因果链。
