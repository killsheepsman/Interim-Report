# 交付经理管理范围质量闭环报告

## 视觉数据输出

正式报告末尾必须遵循 `skills/quality-analysis-core/references/report-visual-contract.md` 输出 `reportKind: "role"` 的 `<REPORT_VISUAL_SPEC_JSON>`。设置 `subject.scopeType: "manager"`，输出工坊或机长对比、下级 TOP 风险、异常趋势和改善期限；不得把工坊汇总值当作交付经理个人异常。

## 1. 角色边界

交付经理是人，是一个或多个工坊的管理责任人，不是工坊名称。报告的选择对象和收件人必须是供应链映射表中的交付经理本人。

管理链固定为：

```text
组装人员（IPQC“送检人”）→ 机长 → 交付经理 → 供应链经理
```

交付经理报告分析其所辖工坊、机长和组装人员的汇总质量状态，重点识别跨人员、跨机长和跨工坊的共同风险，不把下属发生的异常写成交付经理个人问题。

各层责任边界：

- **组装人员**：对本人作业、自检、送检、异常反馈和纠正负责，报告保留具体问题事实。
- **机长**：对班组作业标准、首件、自检、异常升级和复检闭环负责。
- **交付经理**：对工坊资源、跨班组协同、重复问题治理、交付风险和管理机制负责。
- **供应链经理**：对跨工坊资源、供应链机制和交付经理权限外事项负责。

## 2. 管辖范围与数据归属

以供应链映射表建立交付经理的唯一管理范围，至少读取：交付经理、工坊、机长和启用状态。组装人员必须从 IPQC 原始数据的“送检人”字段取得，并通过工坊和机长归入管理链。

严格遵守：

- 不得用工坊名称代替交付经理姓名。
- 不得使用“检验人”“检验员”“判定人”等字段识别组装人员。
- 不得把检验人员纳入组装人员名单。
- 不得仅因原始记录出现某个人名就扩大交付经理的管辖范围。
- 不得跨交付经理、跨工坊借用数据。
- 映射缺失、冲突或一人多属时，单列“映射缺失/映射冲突/待核实”，不得静默分配。

报告开头必须显示：交付经理、所辖工坊、机长数量、组装人员数量、统计周期、数据更新时间、映射完整率和未归属记录数。

## 3. 数据源与指标口径

以 IPQC 原始数据和固定统计引擎结果为主要证据。每条可追溯证据至少保留日期、送检人、工坊、机长、交付经理、项目/产品、送检数量、异常数量、问题类型、纠正状态、复检状态和关闭状态。

### 结果指标

- **送检批次/记录数**：反映工作量，不直接代表质量好坏。
- **送检数量**：按软件既有口径汇总，是异常密度的分母之一。
- **异常数量**：异常件数或异常数量，反映结果暴露。
- **问题记录数**：问题明细行数量，不等同于异常数量。
- **异常密度/异常率**：严格使用项目既有定义，不得用问题记录数或异常发现量代替。
- **重复问题**：同一问题类型、工序、项目或相同证据在规定周期内再次发生。
- **闭环状态**：已纠正、待复检、已验证关闭、逾期或无证据。
- **交付影响**：返工、等待、停线、批量风险或交期影响；无来源时不得推算。

### 管理指标

- 各工坊和机长管理范围的异常密度。
- TOP 问题集中度和多名人员共享问题数量。
- 跨机长、跨工坊重复问题数量。
- 未关闭、逾期和无复检证据问题数量。
- 异常反馈、纠正、复检和关闭的及时性。
- 设备、工装、材料、工艺、标准和资源相关问题。

送检量用于说明工作量，异常密度、重复问题、未关闭/逾期问题和高影响风险才是管理判断重点。不得只按异常数量评价交付经理、工坊或机长。

## 4. 数据审计与证据等级

生成报告前检查：

1. 当前交付经理是否存在于供应链映射表且处于启用状态。
2. 工坊、机长和交付经理是否能建立唯一、完整的逐级关系。
3. 组装人员是否只取自 IPQC“送检人”，检验人员是否被错误纳入。
4. 统计周期和筛选日期是否一致。
5. 送检数量、异常数量、问题记录数和异常密度口径是否与质量数据页面一致。
6. 是否存在重复导入、重复文件或同一记录重复计数。
7. 纠正、复检、关闭和逾期状态是否有可追溯证据。
8. 无法映射和映射冲突的记录是否独立展示。

所有关键结论标注证据等级：

- **已证实**：IPQC 原始记录、固定统计结果或供应链映射表直接支持。
- **合理推断**：多个记录呈现一致模式，但仍需现场验证。
- **待核实**：数据不足以确认，必须形成验证待办。

没有分母、样本量、日期或责任映射时，不输出强结论。

## 5. 报告结构

### 一、管理范围总览

显示交付经理及其所辖工坊、机长、组装人员、统计周期、数据完整性和映射异常。

使用紧凑图表展示：

- 送检量与异常密度趋势。
- 工坊风险分布。
- 机长管理范围风险分布。
- 重复、未关闭和逾期问题状态。

### 二、总体质量结果

分别展示：

- 送检批次、送检数量。
- 异常数量、问题记录数和异常密度/异常率。
- 重复问题、未关闭、逾期和无复检证据问题。
- 高严重度、批量性或影响交付的问题。
- 与上期或目标的变化；没有可比周期或目标时不得虚构改善率。

分子、分母和指标定义必须同时出现，避免把工作量变化误判为质量变化。

### 三、工坊对比

按所辖工坊对比：

- 送检数量和异常密度。
- TOP 问题类型。
- 重复问题和未关闭/逾期问题。
- 设备、工装、材料和工艺风险。
- 趋势和交付影响。

工坊排名优先按风险，不按单一异常总量。样本量不足时标记“样本不足，不作强结论”。

### 四、机长管理范围对比

每位机长只汇总其下属组装人员和所在工坊的数据，展示：

- 送检数量、异常数量和异常密度。
- TOP 问题和重复问题。
- 未关闭、逾期和无复检证据问题。
- 多名下属共享问题。
- 需要交付经理支持的事项。

机长不是具体异常的个人责任对象。交付经理报告只显示管理汇总和 TOP 风险，不复制机长报告全文。

### 五、TOP 组装人员风险

组装人员必须按“送检人”识别。仅列出需要管理者关注的 TOP 风险人员，保留其问题类型、异常密度、重复问题、未关闭/逾期问题和证据链接。

排名优先级：

1. 异常密度/异常率。
2. 重复问题数量。
3. 未关闭和逾期问题。
4. 高严重度或高影响问题。
5. 样本量足够时的异常数量。

不得把送检量大直接解释为质量差，也不得在管理者报告中复制所有个人问题明细。

### 六、管理范围排名与图表

交付经理本人不参加“个人错误排名”。可将当前交付经理的管理范围放入同级交付经理管理范围对比图，用红色五角星、红色姓名和红色数据条突出当前对象，明确这是管理范围风险对比而非个人犯错排名。

正式报告中应使用图表替换重复数据表，图表统一放在对应章节中间，不在报告开头另设重复排名区。建议使用：

- 工坊风险簇状条形图。
- 机长管理范围风险簇状条形图。
- TOP 组装人员风险条形图。
- 问题类型 Pareto 图。
- 月度异常密度与重复问题趋势图。

每个排名注明统计周期、样本量、分母、指标定义和来源。

### 七、跨机长与跨工坊重复问题

识别：

- 多名组装人员重复出现的同类问题。
- 多个机长管理范围共享的同类问题。
- 多个工坊共享的设备、工装、材料、工艺或标准问题。
- 纠正后再次发生、复检后再次发生或长期未关闭的问题。

共享问题优先判定为系统或管理机制风险，不得简单归责某个下属。对每个问题说明首次发生、最近发生、涉及范围、当前控制、剩余风险和升级路径。

### 八、过程与机制根因

沿以下过程还原：

```text
作业标准 → 排产与资源 → 组装执行 → 首件/自检 → 送检 → 异常反馈 → 纠正 → 复检关闭
```

按五层分析：

1. **场景与标准**：作业指导书、图纸、工艺参数和验收标准是否明确且版本一致。
2. **流程与接口**：组装、自检、送检、异常反馈、纠正和复检是否断开。
3. **设备与供应**：设备、工装、材料或供应商状态是否造成重复异常。
4. **决策与证据**：首件、换线、参数变更和异常放行是否留有证据。
5. **资源与治理**：排产、人员、现场支持、跨工坊协调和升级机制是否有效。

不得无证据使用“交付经理管理不到位”“机长失职”“员工粗心”“培训不足”等结论。培训和提醒只能作为临时辅助措施，不能代替流程、防错和验证。

### 九、下属知识考试结果汇总

只有组装人员生成知识考试，交付经理不生成本人考试。报告只汇总所辖组装人员：

- 应参加、已完成、未完成和逾期人数。
- 得分分布和 TOP 错题类型。
- 错题是否对应当前重复问题。
- 考试结果是否已转化为作业标准、班组控制或现场防错。

考试完成或分数合格不能单独证明质量问题关闭，必须有复检、复发率或现场验证证据。

### 十、向供应链经理汇报

必须向供应链经理升级：

- 跨工坊重复出现且交付经理权限内无法消除的问题。
- 设备、工装、材料、供应商或资源配置造成的系统风险。
- 已影响或可能影响交付的批量问题。
- 需要统一标准、系统锁定、预算或跨部门决策的问题。
- 长期逾期、反复放行或没有关闭证据的问题。

汇报采用汇总事实、影响范围、现有控制、剩余风险、所需决策和最后期限，不复制下属个人报告全文。

### 十一、30/60/90 天改善行动

每项行动必须包含问题、作用机制、责任人、协同人、期限、验证指标、证据位置、失效回退和关闭条件。

- **0—30 天：止血**：锁定工坊、机长和组装人员 TOP 风险；隔离批量或重复异常；清理逾期、无复检和无归属问题；明确临时控制。
- **31—60 天：固化**：修订跨班组作业标准、首件、自检、送检、工装防错和异常升级规则；解决共享设备、材料和资源问题。
- **61—90 天：验证**：验证同类问题是否复发，确认异常密度、重复问题和逾期问题是否下降，将有效措施固化到工坊控制清单、系统规则和管理复查机制。

### 十二、验证与关闭条件

问题关闭至少需要：

- 纠正动作已完成并有证据。
- 复检或现场验证通过。
- 规定观察期内未重复发生，或风险指标达到预设目标。
- 相关标准、参数、工装、系统或责任机制已固化。
- 剩余风险已接受并记录批准人和复查日期。

报告生成、会议召开、培训完成、考试合格或表格填写均不能单独作为关闭证据。

## 6. 结论输出格式

按以下顺序形成正式结论：

1. **分析结论**：管理范围内最主要的结果暴露、过程断点和重复风险。
2. **风险判断**：红/橙/黄/绿，说明分子、分母、样本量、影响范围和不确定性。
3. **改善措施**：针对标准、流程、设备、材料、资源、决策或接口机制。
4. **待办事项**：责任人、期限、验证指标、证据位置和关闭条件。

始终保留“结果—过程—根因—责任—行动”证据链。版式采用易读的卡片、图表和行动台账，不输出原始 Markdown 符号，不添加以管理者身份命名的判断标签。

## 7. 禁止事项

- 不得把工坊名称当作交付经理或收件人。
- 不得把机长或组装人员异常写成交付经理个人问题。
- 不得使用检验人员字段识别组装人员。
- 不得跨工坊、跨交付经理借用数据或虚构下属关系。
- 不得用全公司数据替代当前交付经理的管辖范围。
- 不得只按异常数量排名而忽略送检量、异常密度和样本量。
- 不得把送检数量、问题记录数或异常发现量直接当作异常率。
- 不得在没有证据时判断态度、粗心、培训或管理能力原因。
- 不得虚构问题类型、数量、严重度、根因、考试结果、交付影响或关闭结果。
- 不得跨统计周期混用数据。
- 不得用排名图表和数据表重复展示同一内容。
- 不得把报告生成、培训完成或考试合格当作质量问题已关闭。
