# 质量报告排版 Skill

## 网页研究简报接口

保留并透传 `<REPORT_VISUAL_SPEC_JSON>` 的机器含义，但人读版正文不得直接显示该数据块或标题。选择网页研究简报时设置 `layoutProfile: "research-briefing-v1"`，由 `report-web-publisher` 负责 HTML、图表、风险字体颜色和响应式行为。

Markdown 中同源的排名、趋势、分布、构成与对比表，如视觉数据契约中 `tablePolicy` 为 `replace`，只保留图表附近的来源说明；行动、根因、责任、期限、审计口径继续使用表格。

## 目标

把“内容生成”和“视觉呈现”分离。分析 Agent 只提供经过审计的事实、证据和行动；本 Skill 负责把它们排成可扫描、可审阅、可导出的管理报告。不得为了视觉效果新增、改写或推测任何数字。

## 工作流

1. **识别输入**：优先读取结构化 JSON；其次读取带标题和 Markdown 表格的 Markdown；最后才把纯文本按段落处理。保留模块、角色、收件人、统计周期、来源和可信度字段。
2. **建立层级**：按“报告标题 → 统计周期/口径 → 摘要指标 → 重点风险 → 排名图表 → 结果/过程/根因/责任/行动 → 30/60/90 天台账 → 发布门禁”的顺序排版。角色报告必须先显示当事人证据，再显示上级汇总。
3. **渲染组件**：把每个章节转换为组件，而不是把原始 Markdown 直接塞进页面：标题栏、KPI 卡片、风险卡片、图表、表格、证据引用、行动卡片和折叠面板。
4. **应用视觉规范**：使用 `references/style-spec.md` 中的颜色、字体、间距和表格规则。默认 Apple 风格；需要兼容旧界面时切换 Classic 变量，不改变内容结构。
5. **检查完整性**：检查标题是否重复、表格列数是否一致、数字是否带单位、风险颜色是否与等级一致、当事人是否突出、排名图表是否替代重复排名表。
6. **输出**：网页使用语义化 HTML/CSS；导出 Word/PDF 时沿用同一套层级、颜色和分页规则。输出中不添加以管理者身份命名的判断标签。

## 固定组件规则

- 一级标题使用带色背景标题栏，文字必须保持高对比度；红色、橙色、黄色标题栏使用白色标题字，浅蓝、浅紫标题栏使用深色标题字。
- 重点风险用左侧色条或卡片背景标识，不要把整篇正文变成红色。正文默认黑色，证据和来源使用灰色辅助字。
- KPI 卡片只放“指标名、当前值、同期值、变化、可信度”；缺少分母时显示“待核实”，不显示伪精确百分比。
- 排名优先使用簇状条形图。当前当事人用红色五角星和红色数据条；深圳人员名用天蓝色，杭州人员名用紫色，其他数据条用蓝色。
- 对排名、TOP、趋势、分布、结构和同期对比执行“图表替换数据表”；图表必须插入原数据所属章节，隐藏同源数据表，只保留必要的口径和证据说明。
- Pareto 固定使用数量柱形图 + 逐项累加的累计占比折线；良率及月度趋势固定使用数量柱形图 + 良率折线；同期比较保留两期数量和两期比率。
- 组织 × 机制、客户 × 问题、供应商 × 缺陷等二维交叉优先使用热力图；构成变化优先使用堆叠柱形图；变化拆解优先使用瀑布图；关闭时长和项目机台量分布优先使用直方图或分布图。
- 角色报告使用相同的图表替换规则：排名图嵌入排名章节，突出当前报告对象，删除重复排名表。
- 长表格必须允许横向滚动或分页，禁止超出页面；表头固定、数字右对齐、文本左对齐。
- “分析结论—风险判断—改善措施—待办事项”必须和“结果—过程—根因—责任—行动”对应，不得只堆统计数据。
- “数据审计与口径、双重二八与根因证据、三级责任与行动台账”默认折叠；正式报告默认展开并放在最后。
- 正文默认不展示 `S/M/O/C/X` 证据编号，不展示 `REPORT_VISUAL_SPEC_JSON` 或 `ACTION_LEDGER_JSON` 原始代码；保留结论编号、证据等级和行动编号即可。

## 输出契约

推荐输入结构：

```json
{
  "title": "2026年上半年 IPQC 质量复盘",
  "period": "2026-01-01—2026-06-30",
  "scope": "公司级 / 基地 / 交付经理",
  "kpis": [{"label": "异常密度", "current": "4.73%", "prior": "3.15%", "risk": "high"}],
  "risks": [{"title": "重复问题集中", "evidence": "…", "level": "high"}],
  "ranking": [{"name": "张三", "current": 18, "prior": 11, "site": "深圳", "subject": true}],
  "actions": [{"id": "IPQC-01", "owner": "交付经理", "deadline": "30天", "deliverable": "…", "metric": "…"}]
}
```

若输入是 Markdown，先解析标题、表格和列表，再套用同一组件规则；不要把 Markdown 标记原样显示给用户。若字段缺失，显示“待核实/未提供”，不要补数字。
