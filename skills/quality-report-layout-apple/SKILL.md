# Apple 风格质量报告排版

## 核心原则

让结论和证据成为主角。使用克制层级、宽松留白和单一强调语义，不用装饰性渐变、重阴影、大量彩色卡片或冗长开场。

## 输出顺序

1. 只保留一个一级标题，标题下紧接统计周期、分析范围、数据可信度和更新时间。
2. 用一段不超过 120 字的执行摘要直接回答：主要风险在哪里、为什么重要、下一步先做什么。
3. 依次输出关键结果、双重二八、根因证据、三级责任、30/60/90 天行动和关闭条件。
4. 结论先于过程说明；补充口径、证据缺口和发布限制放在后部。
5. 同一排名只表达一次；能用图表表达时不要重复输出文字排名或排名表。

## 图表优先规则

- 对排名、TOP、趋势、分布、供应商对比、缺陷结构和同期对比执行“图表替换数据表”：输出“清晰标题 + 图表就绪 Markdown 数据表”，由页面在同一章节内转换为图表并隐藏原数据表。
- 把图表放在其对应的报告章节，不得集中堆放在报告开头，也不得移动到与数据语义无关的章节。
- Pareto 使用数量柱形图 + 累计占比折线；累计占比必须按排序后的项目逐项累加。
- 良率和月度趋势使用数量柱形图 + 良率折线；同期比较保留 2025/2026 数量与良率系列。
- 人员或管理范围排名使用横向簇状条形图；角色报告突出当前报告对象，不再重复输出排名表。
- 图表数据表第一列必须是类别或时间，其后保留 1—3 个可比较数值系列；不得混合不同量纲。
- 行动、责任、证据、期限、关闭条件和待核实事项保留表格，不强行图形化。
- 图表与数据表不得在正文中重复展示同一组数据。

## Markdown 约束

- 使用 `#`、`##`、`###` 建立三级标题，禁止跳级和重复标题。
- 正文使用短段落；每段只表达一个判断。
- 重点结论用粗体，不给整段文字着色，不使用 emoji 或装饰符号。
- 表格只承载需要逐行比较的内容，列名简短，单元格避免长篇叙述。
- 行动表至少保留：行动、责任对象、期限、验证指标、关闭条件。
- 证据编号、K 结论编号、A 行动编号必须原样保留。

## 质量边界

- 不新增、不重算、不修饰任何数字。
- 不把合理推断改写成已证实事实。
- 不删除证据不足、待核实或发布限制。
- 不把培训、会议、提醒单独写成永久改善措施。
- 输出结构化 Markdown，不输出 CSS、HTML、字体名称或排版说明。
