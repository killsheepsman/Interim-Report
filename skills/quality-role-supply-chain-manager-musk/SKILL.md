# 供应链经理 · 两地经营闭环

本报告由质量部发给供应链经理。看的是杭州、深圳两条线和各交付经理，不是给他本人算个人缺陷。

分析结论必须 3 段，段与段空行。对「你」说话。收件人是供应链经理本人。

## 第1段 公司数 + 两地

只用固定摘要 trend.phrase 和 sites，禁止重算，禁止个人名次。

必须写：各月不良项数、不良率、合计，以及杭州、深圳各自不良项和不良率。

- 数量下降：请继续保持。
- 数量上升：要加油。
- 数量持平：写「数量没有下降」。不良率下降就接「不良率略降」。

目的句：
- 两地都有不良：我们的目的是两地交付前把跨厂、跨交付线的重复问题拦住。
- 只有一地有不良：我们的目的是该厂交付前把跨交付线重复问题拦住。禁止硬写跨厂。

禁止：「当场核对」「这把火在你身上」「供应链经理第几名」。

## 第2段 火在哪条线

没有第2段，结论不合格。不良必须拆开，不许写成「本期不良」。

1. 厂区：sites 有数据就写深圳、杭州项数。一边明显更高，先点那边。
2. 分类 Top3：categories 写类名和项数，分类名只作索引，不当根因。
3. 交付经理：按 teamTop 拆。点名不良最多的交付经理。两个以上才写跨交付线。
4. 机长只作下钻：captainTop 最多写前 3 位，并带交付经理/厂区。不要把全部机长摊开。
5. 周尖峰：用 weekHot。周次只解释尖峰，不能代替厂区和交付经理。
6. 代表事实：有日期+对象+现象才写「代表：」。没有就不要写。禁止待核实、不得编造。

两地同一类都高：写清这是共性问题，要统一标准。只在一地高：点名该交付经理，不要当成公司级标准问题。

sites 或 teamTop 为空时：写清「本期固定摘要还没有厂区/交付经理名单，不能把不良打包结案」，仍写分类和周尖峰。

## 第3段 谁去关

组织交付经理关闭第2段那几类。跨厂、缺标准、缺资源的，由你拍板。

第3段点名的类，必须和措施表每一行对应。

禁止让供应链经理去核对现场螺丝、端子、护盖。那是机长和交付经理的活。

## 本月措施

| 规则 | 要求 |
|---|---|
| 行数 | 按分类 Top3，一类一行，最多 3 行 |
| Owner | 能点到人就写交付经理；两地共性或标准事项写供应链经理 |
| 动作 | 组织交付经理关闭、统一标准、升级拍板 |
| 禁止 | 「当场核对」 |
| 禁止 | 类别写成「本期不良」 |
| 禁止 | 措施 Owner 一律写成供应链经理去拧螺丝 |
| 禁止 | 有分类时按周关单 |

## 固定正文

必须有：质量数据、厂区对比、问题分类、下属交付经理、机长 Top（有不良的前 8 位）。

供应链经理不参与个人排名。排名区域只说明「不参与个人排名」。

## 口吻

- 用「你 / 请你 / 本期」。
- 不用建议关注、赋能、抓手、颗粒度、痛点、闭环机制。
- 不用「质量部的目的」「质量部要求」。
- 继承 quality-role-supply-chain-manager 的数据边界：只用 IPQC 和供应链映射。
